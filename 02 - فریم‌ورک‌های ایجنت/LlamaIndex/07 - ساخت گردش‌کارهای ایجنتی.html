ساخت گردش‌کارهای ایجنتی در LlamaIndex

یک گردش‌کار (Workflow) در LlamaIndex راهی ساختارمند برای سازمان‌دهی کد شما در قالب گام‌های ترتیبی و قابل‌مدیریت فراهم می‌کند.

چنین گردش‌کاری با تعریف Steps (گام‌ها) ساخته می‌شود که توسط Events (رویدادها) فعال می‌شوند و خودشان نیز برای فعال‌کردن گام‌های بعدی Events منتشر می‌کنند. بیایید ببینیم آلفرد یک گردش‌کار LlamaIndex را برای یک وظیفه‌ی RAG نشان می‌دهد.

گردش‌کارها مزیت‌های کلیدی متعددی دارند:

  • سازمان‌دهی روشن کد در قالب گام‌های مجزا
  • معماری رویدادمحور (Event-driven) برای جریان کنترل انعطاف‌پذیر
  • ارتباط ایمن از نظر نوع (Type-safe) بین گام‌ها
  • مدیریت وضعیت (State) داخلی
  • پشتیبانی از تعامل‌های ساده و پیچیده‌ی ایجنتی

همان‌طور که شاید حدس زده باشید، گردش‌کارها تعادل خوبی میان خودمختاری ایجنت‌ها و حفظ کنترل بر کل گردش‌کار برقرار می‌کنند.

پس بیایید یاد بگیریم چگونه خودمان یک گردش‌کار بسازیم!

ساخت یک گردش‌کار پایه

نصب پکیج Workflow

همان‌طور که در بخش LlamaHub معرفی شد، می‌توانیم پکیج Workflow را با دستور زیر نصب کنیم:

pip install llama-index-utils-workflow

می‌توانیم یک گردش‌کار تک‌گامی را با تعریف کلاسی که از Workflow ارث‌بری می‌کند و تزئین (Decorate) توابع با @step بسازیم. همچنین باید StartEvent و StopEvent را اضافه کنیم؛ رویدادهای ویژه‌ای که برای نشان‌دادن شروع و پایان گردش‌کار استفاده می‌شوند.

from llama_index.core.workflow import StartEvent, StopEvent, Workflow, step

class MyWorkflow(Workflow):
    @step
    async def my_step(self, ev: StartEvent) -> StopEvent:
        # اینجا کاری انجام بده
        return StopEvent(result="Hello, world!")


w = MyWorkflow(timeout=10, verbose=False)
result = await w.run()

همان‌طور که می‌بینید، اکنون می‌توانیم با فراخوانی w.run() گردش‌کار را اجرا کنیم.

اتصال چند گام

برای اتصال چند گام، رویدادهای سفارشی می‌سازیم که داده را بین گام‌ها منتقل می‌کنند. برای این کار باید یک Event اضافه کنیم که بین گام‌ها رد و بدل می‌شود و خروجی گام اول را به گام دوم منتقل می‌کند.

from llama_index.core.workflow import Event

class ProcessingEvent(Event):
    intermediate_result: str

class MultiStepWorkflow(Workflow):
    @step
    async def step_one(self, ev: StartEvent) -> ProcessingEvent:
        # پردازش داده‌ی اولیه
        return ProcessingEvent(intermediate_result="Step 1 complete")

    @step
    async def step_two(self, ev: ProcessingEvent) -> StopEvent:
        # استفاده از نتیجه‌ی میانی
        final_result = f"Finished processing: {ev.intermediate_result}"
        return StopEvent(result=final_result)

w = MultiStepWorkflow(timeout=10, verbose=False)
result = await w.run()
result

Type hinting در اینجا مهم است، چون اجرای درست گردش‌کار را تضمین می‌کند. بیایید کمی کار را پیچیده‌تر کنیم!

حلقه‌ها و انشعاب‌ها

Type hinting قدرتمندترین بخش گردش‌کارهاست، چون به ما اجازه می‌دهد انشعاب (Branch)، حلقه (Loop) و اتصال (Join) بسازیم تا گردش‌کارهای پیچیده‌تر را تسهیل کنیم.

بیایید نمونه‌ای از ساخت یک حلقه را با استفاده از عملگر union یعنی | نشان دهیم. در مثال زیر می‌بینیم که LoopEvent به‌عنوان ورودی گام گرفته می‌شود و می‌تواند به‌عنوان خروجی هم برگردانده شود.

from llama_index.core.workflow import Event
import random


class ProcessingEvent(Event):
    intermediate_result: str


class LoopEvent(Event):
    loop_output: str


class MultiStepWorkflow(Workflow):
    @step
    async def step_one(self, ev: StartEvent | LoopEvent) -> ProcessingEvent | LoopEvent:
        if random.randint(0, 1) == 0:
            print("Bad thing happened")
            return LoopEvent(loop_output="Back to step one.")
        else:
            print("Good thing happened")
            return ProcessingEvent(intermediate_result="First step complete.")

    @step
    async def step_two(self, ev: ProcessingEvent) -> StopEvent:
        # استفاده از نتیجه‌ی میانی
        final_result = f"Finished processing: {ev.intermediate_result}"
        return StopEvent(result=final_result)


w = MultiStepWorkflow(verbose=False)
result = await w.run()
result

مدیریت وضعیت (State Management)

مدیریت وضعیت زمانی مفید است که بخواهید وضعیت گردش‌کار را دنبال کنید تا هر گام به همان وضعیت دسترسی داشته باشد. این کار را می‌توان با استفاده از type hint به نام Context روی یکی از پارامترهای تابع گام انجام داد.

from llama_index.core.workflow import Context, StartEvent, StopEvent


@step
async def query(self, ctx: Context, ev: StartEvent) -> StopEvent:
    # ذخیره‌ی کوئری در context
    await ctx.store.set("query", "What is the capital of France?")

    # بازیابی کوئری از context

💡 نکته

نکات ظریف‌تر و پیچیده‌تری درباره‌ی گردش‌کارها وجود دارد که می‌توانید در مستندات LlamaIndex درباره‌ی آن‌ها بخوانید.

با این حال، راه دیگری هم برای ساخت گردش‌کارها وجود دارد که بر کلاس AgentWorkflow تکیه دارد. بیایید ببینیم چگونه می‌توانیم از آن برای ساخت یک گردش‌کار چندایجنتی استفاده کنیم.

خودکارسازی گردش‌کارها با گردش‌کارهای چندایجنتی

به‌جای ساخت دستی گردش‌کار، می‌توانیم از کلاس AgentWorkflow برای ساخت یک گردش‌کار چندایجنتی استفاده کنیم. AgentWorkflow از Workflow Agentها استفاده می‌کند تا به شما اجازه دهد سیستمی از یک یا چند ایجنت بسازید که بر اساس قابلیت‌های تخصصی‌شان بتوانند با هم همکاری کنند و وظایف را به یکدیگر واگذار کنند. این امر ساخت سیستم‌های ایجنتی پیچیده را ممکن می‌کند که در آن ایجنت‌های مختلف جنبه‌های مختلف یک وظیفه را مدیریت می‌کنند. به‌جای ایمپورت کلاس‌ها از llama_index.core.agent، کلاس‌های ایجنت را از llama_index.core.agent.workflow ایمپورت می‌کنیم. یک ایجنت باید در سازنده‌ی AgentWorkflow به‌عنوان ایجنت ریشه (Root Agent) تعیین شود. هنگامی که پیام کاربر می‌رسد، ابتدا به ایجنت ریشه هدایت می‌شود.

هر ایجنت سپس می‌تواند:

  • درخواست را مستقیماً با ابزارهای خود مدیریت کند
  • کار را به ایجنت دیگری که برای وظیفه مناسب‌تر است واگذار (Handoff) کند
  • پاسخی به کاربر برگرداند

بیایید ببینیم چگونه یک گردش‌کار چندایجنتی بسازیم.

from llama_index.core.agent.workflow import AgentWorkflow, ReActAgent
from llama_index.llms.huggingface_api import HuggingFaceInferenceAPI

# تعریف چند ابزار
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

llm = HuggingFaceInferenceAPI(model_name="Qwen/Qwen2.5-Coder-32B-Instruct")

# می‌توانیم توابع را مستقیماً بدون FunctionTool بدهیم -- تابع/docstring برای نام/توضیح پارس می‌شود
multiply_agent = ReActAgent(
    name="multiply_agent",
    description="Is able to multiply two integers",
    system_prompt="A helpful assistant that can use a tool to multiply numbers.",
    tools=[multiply],
    llm=llm,
)

addition_agent = ReActAgent(
    name="add_agent",
    description="Is able to add two integers",
    system_prompt="A helpful assistant that can use a tool to add numbers.",
    tools=[add],
    llm=llm,
)

# ساخت گردش‌کار
workflow = AgentWorkflow(
    agents=[multiply_agent, addition_agent],
    root_agent="multiply_agent",
)

# اجرای سیستم
response = await workflow.run(user_msg="Can you add 5 and 3?")

ابزارهای ایجنت می‌توانند وضعیت گردش‌کار را هم که پیش‌تر اشاره شد تغییر دهند. پیش از شروع گردش‌کار، می‌توانیم یک دیکشنری وضعیت اولیه بدهیم که در دسترس همه‌ی ایجنت‌ها خواهد بود. وضعیت در کلید state از کانتکست گردش‌کار ذخیره می‌شود. این وضعیت در state_prompt تزریق می‌شود که هر پیام جدید کاربر را تقویت می‌کند.

بیایید با تغییر مثال قبلی، یک شمارنده برای شمارش فراخوانی‌های تابع تزریق کنیم:

from llama_index.core.workflow import Context

# تعریف چند ابزار
async def add(ctx: Context, a: int, b: int) -> int:
    """Add two numbers."""
    # به‌روزرسانی شمارنده
    cur_state = await ctx.store.get("state")
    cur_state["num_fn_calls"] += 1
    await ctx.store.set("state", cur_state)

    return a + b

async def multiply(ctx: Context, a: int, b: int) -> int:
    """Multiply two numbers."""
    # به‌روزرسانی شمارنده
    cur_state = await ctx.store.get("state")
    cur_state["num_fn_calls"] += 1
    await ctx.store.set("state", cur_state)

    return a * b

workflow = AgentWorkflow(
    agents=[multiply_agent, addition_agent],
    root_agent="multiply_agent",
    initial_state={"num_fn_calls": 0},
    state_prompt="Current state: {state}. User message: {msg}",

# اجرای گردش‌کار به‌همراه context
ctx = Context(workflow)
response = await workflow.run(user_msg="Can you add 5 and 3?", ctx=ctx)

# بیرون کشیدن و بررسی وضعیت

print(state["num_fn_calls"])
