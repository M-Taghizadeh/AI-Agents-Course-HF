خانه/۰۲ — فریم‌ورک‌های ایجنت/LangGraph/آزمون LangGraph

آزمون سنجش درک شما از LangGraph (Quiz)

بیایید با یک آزمون کوتاه، درک خود از LangGraph را بسنجیم! این آزمون به تثبیت مفاهیم کلیدی‌ای که تاکنون پوشش داده‌ایم کمک می‌کند.

این آزمون اختیاری است و نمره‌ای ندارد. روی گزینه‌ها کلیک کنید تا توضیح آن‌ها را ببینید:

سوال ۱: هدف اصلی LangGraph چیست؟

کدام گزاره به بهترین شکل توصیف می‌کند که LangGraph برای چه کاری طراحی شده است؟

فریم‌ورکی برای ساخت جریان‌های کنترل (Control Flow) برای اپلیکیشن‌هایی که شامل LLM هستند.
درست است! LangGraph به‌طور مشخص برای کمک به ساخت و مدیریت جریان کنترل اپلیکیشن‌هایی طراحی شده که از LLM استفاده می‌کنند.
کتابخانه‌ای که رابط‌هایی برای تعامل با مدل‌های مختلف LLM فراهم می‌کند.
نادرست: این گزاره بیشتر نقش LangChain را توصیف می‌کند که رابط‌های استاندارد برای تعامل با مدل را ارائه می‌دهد. تمرکز LangGraph بر جریان کنترل است.
یک کتابخانه‌ی ایجنت برای فراخوانی ابزار (Tool Calling).
نادرست: اگرچه LangGraph با ایجنت‌ها کار می‌کند، هدف اصلی آن «ارکستراسیون (Orchestration)» است.

سوال ۲: در بده‌بستان «کنترل در برابر آزادی عمل»، جایگاه LangGraph کجاست؟

کدام گزاره به بهترین شکل رویکرد LangGraph در طراحی ایجنت را توصیف می‌کند؟

LangGraph آزادی عمل را به حداکثر می‌رساند و به LLMها اجازه می‌دهد همه‌ی تصمیم‌ها را مستقل بگیرند.
نادرست: LangGraph در واقع بیش از آزادی عمل بر کنترل تمرکز دارد و برای جریان‌های کاری LLM ساختار فراهم می‌کند.
LangGraph کنترل قوی بر جریان اجرا فراهم می‌کند و در عین حال از قابلیت‌های LLM برای تصمیم‌گیری بهره می‌برد.
درست است! LangGraph زمانی می‌درخشد که روی اجرای ایجنت خود کنترل می‌خواهید و از طریق جریان‌های کاری ساختارمند، رفتار قابل‌پیش‌بینی فراهم می‌کند.

سوال ۳: وضعیت (State) در LangGraph چه نقشی دارد؟

دقیق‌ترین توصیف از State در LangGraph را انتخاب کنید.

State آخرین خروجی تولیدشده توسط LLM است.
نادرست: State یک کلاس تعریف‌شده توسط کاربر در LangGraph است و توسط LLM تولید نمی‌شود. فیلدهای آن را کاربر تعریف می‌کند، اما مقادیرشان می‌تواند توسط LLM پر شود.
State فقط برای ردیابی خطاها در حین اجرا استفاده می‌شود.
نادرست: State کاربردی بسیار گسترده‌تر از ردیابی خطا دارد. هرچند همین کاربرد هم مفید است.
State نمایانگر اطلاعاتی است که در اپلیکیشن ایجنتی شما جریان دارد.
درست است! State در LangGraph محوری است و تمام اطلاعات لازم برای تصمیم‌گیری بین مراحل را در خود دارد. شما فیلدهای موردنیاز برای محاسبات را تعریف می‌کنید و نودها می‌توانند مقادیر را تغییر دهند تا درباره‌ی انشعاب تصمیم بگیرند.
State فقط زمانی کاربرد دارد که با APIهای خارجی کار می‌کنید.
نادرست: State برای تمام اپلیکیشن‌های LangGraph اساسی است، نه فقط آن‌هایی که با APIهای خارجی کار می‌کنند.

سوال ۴: یال شرطی (Conditional Edge) در LangGraph چیست؟

دقیق‌ترین توصیف را انتخاب کنید.

یالی که بر اساس ارزیابی یک شرط تعیین می‌کند کدام نود بعداً اجرا شود.
درست است! یال‌های شرطی به گراف شما اجازه می‌دهند بر اساس وضعیت فعلی تصمیمات مسیریابی پویا بگیرد و منطق انشعاب را در جریان کاری شما ایجاد کنند.
یالی که فقط زمانی دنبال می‌شود که یک شرط خاص رخ دهد.
نادرست: یال‌های شرطی جریان اپلیکیشن را بر اساس خروجی‌های آن کنترل می‌کنند، نه ورودی‌اش.
یالی که پیش از ادامه نیاز به تأیید کاربر دارد.
نادرست: یال‌های شرطی بر پایه‌ی شرط‌های برنامه‌نویسی‌شده کار می‌کنند، نه الزام به تعامل کاربر.

سوال ۵: LangGraph چگونه به مسئله‌ی توهم (Hallucination) در LLMها کمک می‌کند؟

بهترین پاسخ را انتخاب کنید.

LangGraph با محدود کردن پاسخ‌های LLM، توهم را به‌طور کامل از بین می‌برد.
نادرست: هیچ فریم‌ورکی نمی‌تواند توهم را به‌طور کامل از LLMها حذف کند و LangGraph هم استثنا نیست.
LangGraph جریان‌های کاری ساختارمندی فراهم می‌کند که می‌توانند خروجی LLM را اعتبارسنجی و راستی‌آزمایی کنند.
درست است! LangGraph با ساخت جریان‌های کاری ساختارمند شامل مراحل اعتبارسنجی، نودهای راستی‌آزمایی و مسیرهای مدیریت خطا، به کاهش تأثیر توهم کمک می‌کند.
LangGraph هیچ تأثیری بر توهم ندارد.
نادرست: رویکرد ساختارمند LangGraph به جریان‌های کاری می‌تواند به‌طور قابل‌توجهی در کاهش توهم کمک کند، البته به قیمت کاهش سرعت.
