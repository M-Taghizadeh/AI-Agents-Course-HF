خانه/۰۲ — فریم‌ورک‌های ایجنت/LangGraph/ساخت اولین گراف با LangGraph

ساخت اولین LangGraph شما: سیستم فیلتر ایمیل آلفرد

اکنون که بلوک‌های بنیادین را شناختیم، بیایید آن‌ها را با ساخت اولین گراف کاربردی‌مان عملی کنیم. سیستم پردازش ایمیل آلفرد را پیاده‌سازی می‌کنیم؛ سیستمی که در آن آلفرد باید:

  1. ایمیل‌های دریافتی را بخواند
  2. آن‌ها را به «اسپم» یا «معتبر» دسته‌بندی کند
  3. برای ایمیل‌های معتبر یک پاسخ اولیه پیش‌نویس کند
  4. در صورت معتبر بودن ایمیل، اطلاعات را برای آقای وین ارسال کند (فقط چاپ می‌شود)

این مثال نشان می‌دهد چگونه جریان کاری‌ای را که شامل تصمیم‌گیری مبتنی بر LLM است با LangGraph ساختار دهیم. اگرچه این سیستم را نمی‌توان یک «ایجنت» دانست (چون هیچ ابزاری در آن دخیل نیست)، تمرکز این بخش بیشتر بر یادگیری خود فریم‌ورک LangGraph است تا ایجنت‌ها.

import os
from typing import TypedDict, List, Dict, Any, Optional
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

مرحله ۱: تعریف State

مشخص می‌کنیم آلفرد در طول جریان پردازش ایمیل باید چه اطلاعاتی را ردیابی کند:

class EmailState(TypedDict):
    # ایمیلی که در حال پردازش است
    email: Dict[str, Any]  # شامل subject، sender، body و غیره

    # دسته‌ی ایمیل (درخواست اطلاعات، شکایت و غیره)
    email_category: Optional[str]

    # دلیل علامت‌گذاری ایمیل به‌عنوان اسپم
    spam_reason: Optional[str]

    # تحلیل‌ها و تصمیم‌ها
    is_spam: Optional[bool]
    
    # تولید پاسخ
    email_draft: Optional[str]
    
    # متادیتای پردازش
    messages: List[Dict[str, Any]]  # ردیابی مکالمه با LLM برای تحلیل
💡 نکته

State را آن‌قدر جامع طراحی کنید که تمام اطلاعات مهم را ردیابی کند، اما از پرکردن آن با جزئیات غیرضروری بپرهیزید.

مرحله ۲: تعریف نودها

اکنون توابع پردازشی‌ای را که نودهای ما را تشکیل می‌دهند ایجاد می‌کنیم:

# مقداردهی اولیه‌ی LLM
model = ChatOpenAI(temperature=0)

def read_email(state: EmailState):
    """Alfred reads and logs the incoming email"""
    email = state["email"]
    
    # اینجا می‌توانیم کمی پیش‌پردازش اولیه انجام دهیم
    print(f"Alfred is processing an email from {email['sender']} with subject: {email['subject']}")
    
    # در اینجا نیازی به تغییر state نیست
    return {}

def classify_email(state: EmailState):
    """Alfred uses an LLM to determine if the email is spam or legitimate"""
    email = state["email"]
    
    # آماده‌سازی پرامپت برای LLM
    prompt = f"""
    As Alfred the butler, analyze this email and determine if it is spam or legitimate.
    
    Email:
    From: {email['sender']}
    Subject: {email['subject']}
    Body: {email['body']}
    
    First, determine if this email is spam. If it is spam, explain why.
    If it is legitimate, categorize it (inquiry, complaint, thank you, etc.).
    """
    
    # فراخوانی LLM
    messages = [HumanMessage(content=prompt)]
    response = model.invoke(messages)
    
    # منطق ساده برای پارس کردن پاسخ (در یک اپلیکیشن واقعی به پارسینگ مقاوم‌تری نیاز دارید)
    response_text = response.content.lower()
    is_spam = "spam" in response_text and "not spam" not in response_text
    
    # اگر اسپم است، دلیل را استخراج می‌کنیم
    spam_reason = None
    if is_spam and "reason:" in response_text:
        spam_reason = response_text.split("reason:")[1].strip()
    
    # اگر معتبر است، دسته را تعیین می‌کنیم
    email_category = None
    if not is_spam:
        categories = ["inquiry", "complaint", "thank you", "request", "information"]
        for category in categories:
            if category in response_text:
                email_category = category
                break
    
    # به‌روزرسانی messages برای ردیابی
    new_messages = state.get("messages", []) + [
        {"role": "user", "content": prompt},
        {"role": "assistant", "content": response.content}
    ]
    
    # بازگرداندن به‌روزرسانی‌های state
    return {
        "is_spam": is_spam,
        "spam_reason": spam_reason,
        "email_category": email_category,
        "messages": new_messages
    }

def handle_spam(state: EmailState):
    """Alfred discards spam email with a note"""
    print(f"Alfred has marked the email as spam. Reason: {state['spam_reason']}")
    print("The email has been moved to the spam folder.")
    
    # پردازش این ایمیل تمام شد
    return {}

def draft_response(state: EmailState):
    """Alfred drafts a preliminary response for legitimate emails"""
    email = state["email"]
    category = state["email_category"] or "general"
    
    # آماده‌سازی پرامپت برای LLM
    prompt = f"""
    As Alfred the butler, draft a polite preliminary response to this email.
    
    Email:
    From: {email['sender']}
    Subject: {email['subject']}
    Body: {email['body']}
    
    This email has been categorized as: {category}
    
    Draft a brief, professional response that Mr. Hugg can review and personalize before sending.
    """
    
    # فراخوانی LLM
    messages = [HumanMessage(content=prompt)]
    response = model.invoke(messages)
    
    # به‌روزرسانی messages برای ردیابی
    new_messages = state.get("messages", []) + [
        {"role": "user", "content": prompt},
        {"role": "assistant", "content": response.content}
    ]
    
    # بازگرداندن به‌روزرسانی‌های state
    return {
        "email_draft": response.content,
        "messages": new_messages
    }

def notify_mr_hugg(state: EmailState):
    """Alfred notifies Mr. Hugg about the email and presents the draft response"""
    email = state["email"]
    
    print("\n" + "="*50)
    print(f"Sir, you've received an email from {email['sender']}.")
    print(f"Subject: {email['subject']}")
    print(f"Category: {state['email_category']}")
    print("\nI've prepared a draft response for your review:")
    print("-"*50)
    print(state["email_draft"])
    print("="*50 + "\n")
    
    # پردازش این ایمیل تمام شد
    return {}

مرحله ۳: تعریف منطق مسیریابی

به تابعی نیاز داریم که پس از دسته‌بندی، مسیر بعدی را مشخص کند:

def route_email(state: EmailState) -> str:
    """Determine the next step based on spam classification"""
    if state["is_spam"]:
        return "spam"
    else:
        return "legitimate"
💡 یادداشت

این تابع مسیریابی توسط LangGraph فراخوانی می‌شود تا تعیین کند پس از نود دسته‌بندی، کدام یال دنبال شود. مقدار بازگشتی باید با یکی از کلیدها در نگاشت یال‌های شرطی ما مطابقت داشته باشد.

مرحله ۴: ساخت StateGraph و تعریف یال‌ها

اکنون همه‌چیز را به هم وصل می‌کنیم:

# ساخت گراف
email_graph = StateGraph(EmailState)

# افزودن نودها
email_graph.add_node("read_email", read_email)
email_graph.add_node("classify_email", classify_email)
email_graph.add_node("handle_spam", handle_spam)
email_graph.add_node("draft_response", draft_response)
email_graph.add_node("notify_mr_hugg", notify_mr_hugg)

# شروع یال‌ها
email_graph.add_edge(START, "read_email")
# افزودن یال‌ها - تعریف جریان
email_graph.add_edge("read_email", "classify_email")

# افزودن انشعاب شرطی از classify_email
email_graph.add_conditional_edges(
    "classify_email",
    route_email,
    {
        "spam": "handle_spam",
        "legitimate": "draft_response"
    }
)

# افزودن یال‌های پایانی
email_graph.add_edge("handle_spam", END)
email_graph.add_edge("draft_response", "notify_mr_hugg")
email_graph.add_edge("notify_mr_hugg", END)

# کامپایل گراف
compiled_graph = email_graph.compile()

توجه کنید که چگونه از نود ویژه‌ی END که توسط LangGraph ارائه می‌شود استفاده کردیم. این نود وضعیت‌های پایانی را مشخص می‌کند، یعنی جایی که جریان کاری تمام می‌شود.

مرحله ۶: بازرسی ایجنت دسته‌بندی ایمیل با Langfuse 📡

همان‌طور که آلفرد ایجنت دسته‌بندی ایمیل را بهبود می‌دهد، از دیباگ کردن اجراهای آن خسته می‌شود. ایجنت‌ها ذاتاً غیرقابل‌پیش‌بینی هستند و بازرسی‌شان دشوار است. اما چون او قصد دارد نهایتاً بهترین ایجنت تشخیص اسپم را بسازد و آن را در محیط پروداکشن مستقر کند، برای پایش و تحلیل‌های آینده به قابلیت ردیابی (Traceability) مطمئنی نیاز دارد.

برای این کار، آلفرد می‌تواند از یک ابزار مشاهده‌پذیری (Observability) مانند Langfuse برای ردیابی و پایش ایجنت استفاده کند.

ابتدا Langfuse را با pip نصب می‌کنیم:

%pip install -q langfuse

سپس LangChain را نصب می‌کنیم (چون از Langfuse استفاده می‌کنیم، LangChain لازم است):

%pip install langchain

در ادامه، کلیدهای API و آدرس هاست Langfuse را به‌عنوان متغیر محیطی اضافه می‌کنیم. می‌توانید با ثبت‌نام در Langfuse Cloud یا میزبانی شخصی (Self-host) Langfuse اطلاعات حساب خود را دریافت کنید.

import os
 
# کلیدهای پروژه‌ی خود را از صفحه‌ی تنظیمات پروژه بگیرید: https://cloud.langfuse.com
os.environ["LANGFUSE_PUBLIC_KEY"] = "pk-lf-..." 
os.environ["LANGFUSE_SECRET_KEY"] = "sk-lf-..."
os.environ["LANGFUSE_HOST"] = "https://cloud.langfuse.com" # 🇪🇺 منطقه‌ی اروپا
# os.environ["LANGFUSE_HOST"] = "https://us.cloud.langfuse.com" # 🇺🇸 منطقه‌ی آمریکا

سپس callback_handler مربوط به Langfuse را پیکربندی می‌کنیم و با افزودن langfuse_callback به فراخوانی گراف، یعنی config={"callbacks": [langfuse_handler]}، ایجنت را ابزارنگاری (Instrument) می‌کنیم.

from langfuse.langchain import CallbackHandler

# مقداردهی اولیه‌ی CallbackHandler مربوط به Langfuse برای LangGraph/Langchain (ردیابی)
langfuse_handler = CallbackHandler()

# پردازش ایمیل معتبر
legitimate_result = compiled_graph.invoke(
    input={"email": legitimate_email, "is_spam": None, "spam_reason": None, "email_category": None, "draft_response": None, "messages": []},
    config={"callbacks": [langfuse_handler]}
)

آلفرد اکنون متصل شده است 🔌! اجراهای LangGraph در Langfuse ثبت می‌شوند و دید کاملی از رفتار ایجنت در اختیار او می‌گذارند. با این پیکربندی، او آماده است اجراهای قبلی را مرور کند و ایجنت دسته‌بندی ایمیل را باز هم بهبود دهد.

لینک عمومی به ردیابی ایمیل معتبر

بصری‌سازی گراف

LangGraph به ما اجازه می‌دهد جریان کاری خود را بصری‌سازی کنیم تا ساختار آن را بهتر بفهمیم و دیباگ کنیم:

compiled_graph.get_graph().draw_mermaid_png()

این کار یک نمایش بصری تولید می‌کند که نشان می‌دهد نودها چگونه به هم متصل‌اند و چه مسیرهای شرطی‌ای می‌توانند طی شوند.

آنچه ساختیم

ما یک جریان کاری کامل پردازش ایمیل ساختیم که:

  1. یک ایمیل ورودی را دریافت می‌کند
  2. با استفاده از یک LLM آن را به «اسپم» یا «معتبر» دسته‌بندی می‌کند
  3. ایمیل‌های اسپم را با دور انداختن مدیریت می‌کند
  4. برای ایمیل‌های معتبر، یک پاسخ پیش‌نویس می‌کند و آقای هاگ (Mr. Hugg) را مطلع می‌سازد

این مثال قدرت LangGraph را در ارکستراسیون جریان‌های کاری پیچیده با LLMها و در عین حال حفظ یک جریان واضح و ساختارمند نشان می‌دهد.

نکات کلیدی

  • مدیریت وضعیت (State Management): یک State جامع تعریف کردیم تا تمام جنبه‌های پردازش ایمیل را ردیابی کند.
  • پیاده‌سازی نودها: نودهای کاربردی‌ای ساختیم که با یک LLM تعامل می‌کنند.
  • مسیریابی شرطی: منطق انشعاب بر اساس دسته‌بندی ایمیل را پیاده‌سازی کردیم.
  • وضعیت‌های پایانی: از نود END برای مشخص کردن نقاط تکمیل جریان کاری استفاده کردیم.

گام بعدی چیست؟

در بخش بعد، قابلیت‌های پیشرفته‌تر LangGraph را بررسی می‌کنیم، از جمله مدیریت تعامل انسان در جریان کاری و پیاده‌سازی منطق انشعاب پیچیده‌تر بر اساس چند شرط.
