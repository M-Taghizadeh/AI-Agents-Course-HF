خانه/۰۲ — فریم‌ورک‌های ایجنت/LangGraph/اجزای بنیادین LangGraph

اجزای بنیادین LangGraph (Building Blocks)

برای ساخت اپلیکیشن با LangGraph باید اجزای هسته‌ی آن را بشناسید. بیایید بلوک‌های بنیادینی را که یک اپلیکیشن LangGraph را می‌سازند بررسی کنیم.

یک اپلیکیشن در LangGraph از یک نقطه ورود (Entrypoint) شروع می‌شود و بسته به نحوه‌ی اجرا، جریان ممکن است به یک تابع یا تابع دیگر برود تا به END برسد.

۱. وضعیت (State)

State مفهوم محوری در LangGraph است. این بخش تمام اطلاعاتی را که در اپلیکیشن شما جریان دارد نمایش می‌دهد.

from typing_extensions import TypedDict

class State(TypedDict):
    graph_state: str

وضعیت توسط کاربر تعریف می‌شود، بنابراین فیلدها را باید با دقت طراحی کنید تا شامل تمام داده‌های لازم برای فرایند تصمیم‌گیری باشند!

💡 نکته

به‌دقت فکر کنید که اپلیکیشن شما باید چه اطلاعاتی را بین مراحل ردیابی کند.

۲. نودها (Nodes)

نودها توابع پایتون هستند. هر نود:

  • وضعیت (State) را به‌عنوان ورودی می‌گیرد.
  • عملیاتی را انجام می‌دهد.
  • به‌روزرسانی‌های وضعیت را برمی‌گرداند.
def node_1(state):
    print("---Node 1---")
    return {"graph_state": state['graph_state'] +" I am"}

def node_2(state):
    print("---Node 2---")
    return {"graph_state": state['graph_state'] +" happy!"}

def node_3(state):
    print("---Node 3---")
    return {"graph_state": state['graph_state'] +" sad!"}

برای مثال، نودها می‌توانند شامل موارد زیر باشند:

  • فراخوانی LLM: تولید متن یا گرفتن تصمیم.
  • فراخوانی ابزار: تعامل با سیستم‌های خارجی.
  • منطق شرطی: تعیین گام‌های بعدی.
  • مداخله‌ی انسان: دریافت ورودی از کاربران.
💡 اطلاعات

برخی نودهای ضروری برای کل جریان کاری، مانند START و END، مستقیماً توسط خود LangGraph ارائه می‌شوند.

۳. یال‌ها (Edges)

یال‌ها نودها را به هم وصل می‌کنند و مسیرهای ممکن در گراف شما را تعریف می‌کنند:

import random
from typing import Literal

def decide_mood(state) -> Literal["node_2", "node_3"]:
    
    # اغلب از state برای تصمیم‌گیری درباره‌ی نود بعدی استفاده می‌کنیم
    user_input = state['graph_state'] 
    
    # اینجا فقط یک تقسیم ۵۰ / ۵۰ بین نودهای ۲ و ۳ انجام می‌دهیم
    if random.random() < 0.5:

        # در ۵۰٪ مواقع نود ۲ را برمی‌گردانیم
        return "node_2"
    
    # در ۵۰٪ مواقع نود ۳ را برمی‌گردانیم
    return "node_3"

یال‌ها می‌توانند از این نوع باشند:

  • مستقیم (Direct): همیشه از نود A به نود B می‌روند.
  • شرطی (Conditional): نود بعدی را بر اساس وضعیت فعلی انتخاب می‌کنند.

۴. گراف وضعیت (StateGraph)

StateGraph کانتینری است که کل جریان کاری ایجنت شما را در خود نگه می‌دارد:

from IPython.display import Image, display
from langgraph.graph import StateGraph, START, END

# ساخت گراف
builder = StateGraph(State)
builder.add_node("node_1", node_1)
builder.add_node("node_2", node_2)
builder.add_node("node_3", node_3)

# منطق
builder.add_edge(START, "node_1")
builder.add_conditional_edges("node_1", decide_mood)
builder.add_edge("node_2", END)
builder.add_edge("node_3", END)

# کامپایل
graph = builder.compile()

که سپس می‌توان آن را بصری‌سازی کرد!

# نمایش
display(Image(graph.get_graph().draw_mermaid_png()))

اما مهم‌تر از همه، می‌توان آن را اجرا (invoke) کرد:

graph.invoke({"graph_state" : "Hi, this is Lance."})

خروجی:

---Node 1---
---Node 3---
{'graph_state': 'Hi, this is Lance. I am sad!'}

گام بعدی چیست؟

در بخش بعد، این مفاهیم را با ساخت اولین گراف خودمان عملی می‌کنیم. این گراف به آلفرد اجازه می‌دهد ایمیل‌های شما را دریافت کند، آن‌ها را دسته‌بندی کند و اگر ایمیل واقعی و معتبر بود، یک پاسخ اولیه تهیه کند.
