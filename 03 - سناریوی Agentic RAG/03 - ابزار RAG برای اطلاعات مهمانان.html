خانه/۰۳ — سناریوی Agentic RAG/ابزار RAG برای اطلاعات مهمانان

ساخت ابزار RAG برای داستان‌های مهمانان

آلفرد، ایجنت قابل‌اعتماد شما، در حال آماده‌سازی مجلل‌ترین جشن قرن است. برای اینکه مراسم روان پیش برود، آلفرد به دسترسی سریع به اطلاعات به‌روز درباره هر مهمان نیاز دارد. بیایید با ساخت یک ابزار سفارشی تولید افزوده با بازیابی (RAG) که با مجموعه‌داده اختصاصی ما کار می‌کند، به او کمک کنیم.

چرا RAG برای یک جشن؟

تصور کنید آلفرد در میان مهمانان رفت‌وآمد می‌کند و باید در یک لحظه جزئیات مشخصی را درباره هر فرد به یاد بیاورد. یک LLM سنتی ممکن است در این کار مشکل داشته باشد، زیرا:

  1. فهرست مهمانان مخصوص رویداد شماست و در داده‌های آموزشی مدل نیست
  2. اطلاعات مهمانان ممکن است مرتباً تغییر کند یا به‌روزرسانی شود
  3. آلفرد باید جزئیات دقیقی مانند آدرس ایمیل را بازیابی کند

اینجاست که تولید افزوده با بازیابی (RAG) می‌درخشد! با ترکیب یک سیستم بازیابی با یک LLM، آلفرد می‌تواند هر زمان لازم باشد به اطلاعات دقیق و به‌روز مهمانان دسترسی پیدا کند.

نکته: برای این سناریو می‌توانید هر یک از فریم‌ورک‌های پوشش‌داده‌شده در دوره را انتخاب کنید. در این نسخه، کد هر فریم‌ورک زیر عنوان جداگانه‌ای آمده است.

راه‌اندازی برنامه

در این واحد، ایجنت خود را درون یک HF Space و به صورت یک پروژه ساختاریافته پایتون توسعه می‌دهیم. این رویکرد به ما کمک می‌کند با سازماندهی قابلیت‌های مختلف در فایل‌های جداگانه، کدی تمیز و ماژولار داشته باشیم. همچنین سناریوی واقعی‌تری است، چون برنامه برای استفاده عمومی مستقر می‌شود.

ساختار پروژه

  • tools.py – ابزارهای کمکی ایجنت را فراهم می‌کند.
  • retriever.py – توابع بازیابی را برای پشتیبانی از دسترسی به دانش پیاده می‌کند.
  • app.py – همه اجزا را در یک ایجنت کاملاً کاربردی یکپارچه می‌کند که در بخش آخر این واحد نهایی‌اش می‌کنیم.

برای مرجع عملی، این HF Space را ببینید که Agentic RAG توسعه‌یافته در این واحد در آن فعال است. می‌توانید آن را کلون کنید و با آن آزمایش کنید!

می‌توانید ایجنت را مستقیماً در پایین امتحان کنید:

مرور مجموعه‌داده

مجموعه‌داده ما، agents-course/unit3-invitees، برای هر مهمان فیلدهای زیر را دارد:

  • Relation: نسبت مهمان با میزبان
  • Description: زندگی‌نامه کوتاه یا نکات جالب درباره مهمان

نکته: در یک سناریوی واقعی، این مجموعه‌داده می‌تواند گسترش یابد و شامل ترجیحات غذایی، علایق هدیه، موضوعات گفتگویی که باید از آن‌ها پرهیز شود و سایر جزئیات مفید برای یک میزبان باشد.

گام ۲: ساخت ابزار بازیابی

حالا یک ابزار سفارشی می‌سازیم که آلفرد بتواند با آن در اطلاعات مهمانان جستجو کند.

smolagents

برای ساخت ابزار بازیابی از BM25Retriever در ماژول langchain_community.retrievers استفاده می‌کنیم.

نکته: BM25Retriever نقطه شروع خوبی برای بازیابی است، اما برای جستجوی معنایی پیشرفته‌تر می‌توانید بازیاب‌های مبتنی بر embedding مانند نمونه‌های sentence-transformers را در نظر بگیرید.

from smolagents import Tool
from langchain_community.retrievers import BM25Retriever

class GuestInfoRetrieverTool(Tool):
    name = "guest_info_retriever"
    description = "Retrieves detailed information about gala guests based on their name or relation."
    inputs = {
        "query": {
            "type": "string",
            "description": "The name or relation of the guest you want information about."
        }
    }
    output_type = "string"

    def __init__(self, docs):
        self.is_initialized = False
        self.retriever = BM25Retriever.from_documents(docs)

    def forward(self, query: str):
        results = self.retriever.invoke(query)
        if results:
            return "\n\n".join([doc.page_content for doc in results[:3]])
        else:
            return "No matching guest information found."

# Initialize the tool
guest_info_tool = GuestInfoRetrieverTool(docs)

بیایید این ابزار را گام‌به‌گام بفهمیم:

  • name و description به ایجنت کمک می‌کنند بفهمد چه زمانی و چگونه از این ابزار استفاده کند
  • inputs مشخص می‌کند ابزار چه پارامترهایی انتظار دارد (در اینجا یک پرسش جستجو)
  • از BM25Retriever استفاده می‌کنیم؛ الگوریتمی قدرتمند برای بازیابی متن که به embedding نیاز ندارد
  • متد forward پرسش را پردازش می‌کند و مرتبط‌ترین اطلاعات مهمان را برمی‌گرداند

LlamaIndex

برای ساخت ابزار بازیابی از BM25Retriever در ماژول llama_index.retrievers.bm25 استفاده می‌کنیم.

نکته: BM25Retriever نقطه شروع خوبی برای بازیابی است، اما برای جستجوی معنایی پیشرفته‌تر می‌توانید بازیاب‌های مبتنی بر embedding مانند نمونه‌های sentence-transformers را در نظر بگیرید.

from llama_index.core.tools import FunctionTool
from llama_index.retrievers.bm25 import BM25Retriever

bm25_retriever = BM25Retriever.from_defaults(nodes=docs)

def get_guest_info_retriever(query: str) -> str:
    """Retrieves detailed information about gala guests based on their name or relation."""
    results = bm25_retriever.retrieve(query)
    if results:
        return "\n\n".join([doc.text for doc in results[:3]])
    else:
        return "No matching guest information found."

# Initialize the tool
guest_info_tool = FunctionTool.from_defaults(get_guest_info_retriever)

بیایید این ابزار را گام‌به‌گام بفهمیم:

  • docstring به ایجنت کمک می‌کند بفهمد چه زمانی و چگونه از این ابزار استفاده کند
  • نوع‌نماها (type hints) مشخص می‌کنند ابزار چه پارامترهایی انتظار دارد (در اینجا یک پرسش جستجو)
  • از BM25Retriever استفاده می‌کنیم؛ الگوریتمی قدرتمند برای بازیابی متن که به embedding نیاز ندارد
  • این متد پرسش را پردازش می‌کند و مرتبط‌ترین اطلاعات مهمان را برمی‌گرداند

گام ۳: یکپارچه‌سازی ابزار با آلفرد

در نهایت همه‌چیز را کنار هم می‌گذاریم: ایجنت را می‌سازیم و آن را به ابزار سفارشی‌مان مجهز می‌کنیم:

smolagents

from smolagents import CodeAgent, InferenceClientModel

# Initialize the Hugging Face model
model = InferenceClientModel()

# Create Alfred, our gala agent, with the guest info tool

# Example query Alfred might receive during the gala
response = alfred.run("Tell me about our guest named 'Lady Ada Lovelace'.")

print("🎩 Alfred's Response:")
print(response)

from llama_index.core.agent.workflow import AgentWorkflow

LangGraph

from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages
from langchain_core.messages import AnyMessage, HumanMessage, AIMessage
from langgraph.prebuilt import ToolNode
from langgraph.graph import START, StateGraph
from langgraph.prebuilt import tools_condition
from langchain_huggingface import HuggingFaceEndpoint, ChatHuggingFace

# Generate the chat interface, including the tools
llm = HuggingFaceEndpoint(
    repo_id="Qwen/Qwen2.5-Coder-32B-Instruct",
    huggingfacehub_api_token=HUGGINGFACEHUB_API_TOKEN,
)

chat = ChatHuggingFace(llm=llm, verbose=True)
tools = [guest_info_tool]
chat_with_tools = chat.bind_tools(tools)

# Generate the AgentState and Agent graph
class AgentState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]

def assistant(state: AgentState):
    return {
        "messages": [chat_with_tools.invoke(state["messages"])],
    }

## The graph
builder = StateGraph(AgentState)

# Define nodes: these do the work
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))

# Define edges: these determine how the control flow moves
builder.add_edge(START, "assistant")
builder.add_conditional_edges(
    "assistant",
    # If the latest message requires a tool, route to tools
    # Otherwise, provide a direct response
    tools_condition,
)
builder.add_edge("tools", "assistant")
alfred = builder.compile()

messages = [HumanMessage(content="Tell me about our guest named 'Lady Ada Lovelace'.")]
response = alfred.invoke({"messages": messages})

print("🎩 Alfred's Response:")
print(response['messages'][-1].content)

خروجی مورد انتظار:

🎩 Alfred's Response:
Lady Ada Lovelace is an esteemed mathematician and pioneer in computing, often celebrated as the first computer programmer due to her work on Charles Babbage's Analytical Engine.

در این گام نهایی چه اتفاقی می‌افتد:

  • با کلاس HuggingFaceEndpoint یک مدل Hugging Face را مقداردهی اولیه می‌کنیم. همچنین یک رابط چت می‌سازیم و ابزارها را به آن اضافه می‌کنیم
  • ایجنت خود (آلفرد) را به صورت یک StateGraph می‌سازیم که ۲ گره (assistant و tools) را با یک یال ترکیب می‌کند
  • از آلفرد می‌خواهیم اطلاعات مهمانی به نام «Lady Ada Lovelace» را بازیابی کند
