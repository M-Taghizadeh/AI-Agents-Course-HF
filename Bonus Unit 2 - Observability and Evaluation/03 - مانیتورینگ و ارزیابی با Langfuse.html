گام ۱: ابزارگذاری ایجنت (Instrument Your Agent)

در این نوت‌بوک از Langfuse به‌عنوان ابزار مشاهده‌پذیری استفاده می‌کنیم، اما می‌توانید از هر سرویس دیگری که با OpenTelemetry سازگار است استفاده کنید. کد زیر نشان می‌دهد چگونه متغیرهای محیطی را برای Langfuse (یا هر endpoint سازگار با OTel) تنظیم کنید و smolagent خود را ابزارگذاری کنید.

توجه

اگر از LlamaIndex یا LangGraph استفاده می‌کنید، مستندات ابزارگذاری آن‌ها را اینجا و اینجا می‌توانید پیدا کنید.

ابتدا اعتبارنامه‌های Langfuse را به‌صورت متغیرهای محیطی تنظیم می‌کنیم. کلیدهای API لنگ‌فیوز را با ثبت‌نام در Langfuse Cloud یا میزبانی شخصی (Self-hosting) Langfuse دریافت کنید.

os.environ["LANGFUSE_SECRET_KEY"] = "sk-lf-..."
os.environ["LANGFUSE_HOST"] = "https://cloud.langfuse.com" # 🇪🇺 EU region
# os.environ["LANGFUSE_HOST"] = "https://us.cloud.langfuse.com" # 🇺🇸 US region

گام ۲: ابزارگذاری خود را آزمایش کنید

در اینجا یک CodeAgent ساده از smolagents داریم که 1+1 را محاسبه می‌کند. آن را اجرا می‌کنیم تا از درست کار کردن ابزارگذاری مطمئن شویم. اگر همه‌چیز درست تنظیم شده باشد، لاگ‌ها/Spanها را در داشبورد مشاهده‌پذیری خود می‌بینید.

گام ۳: مشاهده و ارزیابی یک ایجنت پیچیده‌تر

ساختار Trace

بیشتر ابزارهای مشاهده‌پذیری یک Trace ثبت می‌کنند که شامل Spanها است و هر کدام یک گام از منطق ایجنت شما را نشان می‌دهند. در اینجا، Trace شامل اجرای کلی ایجنت و Spanهای فرعی برای موارد زیر است:

  • فراخوانی‌های ابزار (DuckDuckGoSearchTool)
  • فراخوانی‌های LLM (InferenceClientModel)

می‌توانید این‌ها را بررسی کنید تا دقیقاً ببینید زمان کجا صرف می‌شود، چند توکن مصرف شده و غیره:

ارزیابی آنلاین (Online Evaluation)

در بخش قبل، تفاوت میان ارزیابی آنلاین و آفلاین را یاد گرفتیم. اکنون می‌بینیم چگونه ایجنت خود را در پروداکشن پایش و به‌صورت زنده ارزیابی کنیم.

متریک‌های رایج برای پیگیری در پروداکشن

  1. هزینه‌ها (Costs) — ابزارگذاری smolagents مصرف توکن را ثبت می‌کند، که با تعیین قیمت به‌ازای هر توکن می‌توانید آن را به هزینه‌ی تقریبی تبدیل کنید.
  2. تاخیر زمانی (Latency) — زمان لازم برای تکمیل هر گام یا کل اجرا را مشاهده کنید.
  3. بازخورد کاربر (User Feedback) — کاربران می‌توانند بازخورد مستقیم (لایک/دیس‌لایک) بدهند تا ایجنت اصلاح یا بهبود یابد.
  4. LLM-as-a-Judge — از یک LLM جداگانه برای ارزیابی خروجی ایجنت تقریباً به‌صورت بلادرنگ استفاده کنید (مثلاً بررسی سمّی بودن یا درستی).

در ادامه نمونه‌هایی از این متریک‌ها را نشان می‌دهیم.

۳. ویژگی‌های اضافی (Additional Attributes)

همچنین می‌توانید ویژگی‌های اضافی را به Spanهای خود پاس دهید. این‌ها می‌توانند شامل user_id، tags، session_id و فراداده‌ی سفارشی باشند. غنی‌سازی Traceها با این جزئیات برای تحلیل، دیباگ و پایش رفتار اپلیکیشن شما در میان کاربران یا نشست‌های مختلف مهم است.

from smolagents import (CodeAgent, DuckDuckGoSearchTool, InferenceClientModel)

search_tool = DuckDuckGoSearchTool()
agent = CodeAgent(
    tools=[search_tool],
    model=InferenceClientModel()
)

with langfuse.start_as_current_span(
    name="Smolagent-Trace",
    ) as span:
    
    # اپلیکیشن خود را اینجا اجرا کنید
    response = agent.run("What is the capital of Germany?")
 
    # ویژگی‌های اضافی را به span پاس دهید
    span.update_trace(
        input="What is the capital of Germany?",
        output=response,
        user_id="smolagent-user-123",
        session_id="smolagent-session-123456789",
        tags=["city-question", "testing-agents"],
        metadata={"email": "user@langfuse.com"},
        )
 
# در اپلیکیشن‌های کوتاه‌مدت، رویدادها را Flush کنید
langfuse.flush()

۴. بازخورد کاربر (User Feedback)

اگر ایجنت شما در یک رابط کاربری تعبیه شده است، می‌توانید بازخورد مستقیم کاربر را (مانند لایک/دیس‌لایک در رابط چت) ثبت کنید. در ادامه نمونه‌ای با Gradio آمده که یک چت با مکانیزم ساده‌ی بازخورد تعبیه می‌کند.

در قطعه کد زیر، وقتی کاربر پیام چت می‌فرستد، Trace را در Langfuse ثبت می‌کنیم. اگر کاربر آخرین پاسخ را لایک/دیس‌لایک کند، یک نمره (Score) به Trace الصاق می‌کنیم.

import gradio as gr
from smolagents import (CodeAgent, InferenceClientModel)
from langfuse import get_client

langfuse = get_client()

model = InferenceClientModel()
agent = CodeAgent(tools=[], model=model, add_base_tools=True)

trace_id = None

def respond(prompt, history):
    with langfuse.start_as_current_span(
        name="Smolagent-Trace"):
        
        # اپلیکیشن خود را اینجا اجرا کنید
        output = agent.run(prompt)

        global trace_id
        trace_id = langfuse.get_current_trace_id()

    history.append({"role": "assistant", "content": str(output)})
    return history

def handle_like(data: gr.LikeData):
    # برای نمایش، بازخورد کاربر را به ۱ (لایک) یا ۰ (دیس‌لایک) نگاشت می‌کنیم
    if data.liked:
        langfuse.create_score(
            value=1,
            name="user-feedback",
            trace_id=trace_id
        )
    else:
        langfuse.create_score(
            value=0,
            name="user-feedback",
            trace_id=trace_id
        )

with gr.Blocks() as demo:
    chatbot = gr.Chatbot(label="Chat", type="messages")
    prompt_box = gr.Textbox(placeholder="Type your message...", label="Your message")

    # وقتی کاربر Enter را روی پرامپت می‌زند، 'respond' را اجرا می‌کنیم
    prompt_box.submit(
        fn=respond,
        inputs=[prompt_box, chatbot],
        outputs=chatbot
    )

    # وقتی کاربر روی دکمه‌ی 'like' یک پیام کلیک می‌کند، 'handle_like' را اجرا می‌کنیم
    chatbot.like(handle_like, None, None)

demo.launch()

۵. LLM-as-a-Judge

LLM-as-a-Judge راه دیگری برای ارزیابی خودکار خروجی ایجنت است. می‌توانید یک فراخوانی LLM جداگانه راه بیندازید تا درستی، سمّی بودن، سبک یا هر معیار دیگری را که برایتان مهم است بسنجد.

گردش‌کار:

  1. یک قالب ارزیابی (Evaluation Template) تعریف می‌کنید؛ مثلاً «بررسی کن آیا متن سمّی است.»
  2. هر بار که ایجنت شما خروجی تولید می‌کند، آن خروجی را همراه با قالب به LLM «داور» خود می‌دهید.
  3. LLM داور با یک امتیاز یا برچسب پاسخ می‌دهد که آن را در ابزار مشاهده‌پذیری خود ثبت می‌کنید.

نمونه از Langfuse:

# مثال: بررسی اینکه خروجی ایجنت سمی (Toxic) هست یا نه
from smolagents import (CodeAgent, DuckDuckGoSearchTool, InferenceClientModel)

search_tool = DuckDuckGoSearchTool()
agent = CodeAgent(tools=[search_tool], model=InferenceClientModel())

agent.run("Can eating carrots improve your vision?")

می‌توانید ببینید که پاسخ این مثال «غیرسمّی» (not toxic) ارزیابی شده است.

۶. نمای کلی متریک‌های مشاهده‌پذیری

همه‌ی این متریک‌ها را می‌توان در داشبوردها با هم نمایش داد. این به شما اجازه می‌دهد سریع ببینید ایجنت شما در نشست‌های زیاد چگونه عمل می‌کند و در پیگیری متریک‌های کیفیت در طول زمان کمک می‌کند.

ارزیابی آفلاین (Offline Evaluation)

ارزیابی آنلاین برای بازخورد زنده ضروری است، اما به ارزیابی آفلاین هم نیاز دارید، یعنی بررسی‌های سیستماتیک پیش از توسعه یا در حین آن. این به حفظ کیفیت و قابلیت اطمینان پیش از انتشار تغییرات در پروداکشن کمک می‌کند.

ارزیابی با دیتاست (Dataset Evaluation)

در ارزیابی آفلاین معمولاً:

  1. یک دیتاست بنچ‌مارک دارید (با جفت‌های پرامپت و خروجی مورد انتظار)
  2. ایجنت خود را روی آن دیتاست اجرا می‌کنید
  3. خروجی‌ها را با نتایج مورد انتظار مقایسه می‌کنید یا از یک مکانیزم نمره‌دهی اضافی استفاده می‌کنید

در ادامه این رویکرد را با دیتاست GSM8K که شامل سوالات و راه‌حل‌های ریاضی است نشان می‌دهیم.

import pandas as pd
from datasets import load_dataset

# دریافت GSM8K از Hugging Face
dataset = load_dataset("openai/gsm8k", 'main', split='train')
df = pd.DataFrame(dataset)
print("First few rows of GSM8K dataset:")
print(df.head())

سپس یک موجودیت دیتاست در Langfuse می‌سازیم تا اجراها را پیگیری کنیم. بعد هر آیتم از دیتاست را به سیستم اضافه می‌کنیم. (اگر از Langfuse استفاده نمی‌کنید، می‌توانید این‌ها را ساده‌تر در پایگاه داده‌ی خودتان یا یک فایل محلی برای تحلیل ذخیره کنید.)

from langfuse import get_client

langfuse_dataset_name = "gsm8k_dataset_huggingface"

# ساخت یک دیتاست در Langfuse

for idx, row in df.iterrows():

    if idx >= 9: # برای نمایش، فقط ۱۰ آیتم اول آپلود می‌شود

اجرای ایجنت روی دیتاست

یک تابع کمکی به نام run_smolagent() تعریف می‌کنیم که:

  1. یک Span در Langfuse شروع می‌کند
  2. ایجنت ما را روی پرامپت اجرا می‌کند
  3. شناسه‌ی Trace را در Langfuse ثبت می‌کند

سپس روی هر آیتم دیتاست حلقه می‌زنیم، ایجنت را اجرا می‌کنیم و Trace را به آیتم دیتاست پیوند می‌دهیم. در صورت تمایل می‌توانیم یک نمره‌ی ارزیابی سریع هم الصاق کنیم.

from opentelemetry.trace import format_trace_id
from smolagents import (CodeAgent, InferenceClientModel, LiteLLMModel)
from langfuse import get_client
 
langfuse = get_client()


# مثال: استفاده از InferenceClientModel یا LiteLLMModel برای دسترسی به مدل‌های openai، anthropic، gemini و غیره:
model = InferenceClientModel()

agent = CodeAgent(
    tools=[],
    model=model,
    add_base_tools=True
)

dataset_name = "gsm8k_dataset_huggingface"
current_run_name = "smolagent-notebook-run-01" # این اجرای ارزیابی مشخص را شناسایی می‌کند
 
# فرض کنید 'run_smolagent' تابع اپلیکیشن ابزارگذاری‌شده‌ی شماست
def run_smolagent(question):
    with langfuse.start_as_current_generation(name="qna-llm-call") as generation:
        # شبیه‌سازی فراخوانی LLM
        result = agent.run(question)
 
        # Trace را با ورودی و خروجی به‌روز کن
        generation.update_trace(
            input= question,
            output=result,
        )
 
        return result
 
dataset = langfuse.get_dataset(name=dataset_name) # دیتاست از پیش پرشده‌ی خود را بگیرید
 
for item in dataset.items:
 
    # از context manager متد item.run() استفاده کنید
    with item.run(
        run_name=current_run_name,
        run_metadata={"model_provider": "Hugging Face", "temperature_setting": 0.7},
        run_description="Evaluation run for GSM8K dataset"
    ) as root_span: # root_span همان span ریشه‌ی Trace جدید برای این آیتم و این اجراست.
        # همه‌ی عملیات Langfuse بعدی داخل این بلاک بخشی از این Trace هستند.
 
        # منطق اپلیکیشن خود را صدا بزنید
        generated_answer = run_smolagent(question=item.input["text"])
 
        print(item.input)

می‌توانید این فرایند را با موارد مختلف تکرار کنید:

  • مدل‌ها (OpenAI GPT، LLM محلی و غیره)
  • ابزارها (با جست‌وجو در برابر بدون جست‌وجو)
  • پرامپت‌ها (پیام‌های سیستمی مختلف)

  1. مشاهده‌پذیری را راه‌اندازی کنیم با استفاده از smolagents + OpenTelemetry exporters
  2. ابزارگذاری را بررسی کنیم با اجرای یک ایجنت ساده
  3. متریک‌های دقیق (هزینه، تاخیر و غیره) را ثبت کنیم از طریق ابزارهای مشاهده‌پذیری
  4. بازخورد کاربر را جمع‌آوری کنیم از طریق یک رابط Gradio
  5. از LLM-as-a-Judge استفاده کنیم برای ارزیابی خودکار خروجی‌ها
  6. ارزیابی آفلاین انجام دهیم با یک دیتاست بنچ‌مارک
